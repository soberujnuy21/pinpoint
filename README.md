# pinpoint

과제, 발표, 보고서, 지원서가 "좋은가"가 아니라 **"평가자가 원하는 그것인가"**를 보는 Claude Code skill.

안내문·채점표·강의자료와 결과물을 대조해서 요구사항 누락, 배점과 공력 배분의 어긋남, 강의 기본값에서 벗어난 선택의 근거 부재, 내부 모순, 지식의 깊이를 판정합니다. 결과는 평가자(교수자, 심사위원, 채용 담당자 등)가 제출자에게 보내는 검토 메일로 받습니다. 다시 써 주지 않고 방향만 교정합니다.

## 설치

```bash
git clone https://github.com/soberujnuy21/pinpoint.git ~/.claude/skills/pinpoint
```

## 사용

```
/pinpoint <안내문 경로 또는 본문> [제출물 경로]
```

```
/pinpoint "과제7/안내문/실습문제7.pptx" "과제7/제출/실습문제7_완성.ipynb"
```

- 대화 맥락과 분리된 fork 에이전트에서 실행됩니다. 평가자처럼 안내문과 결과물만 보고 판단합니다.
- 경로가 폴더면 안의 파일을 모두 읽습니다. 강의자료나 참고 코드를 같은 폴더에 넣어 두면 "강의 기본값"과 "기대 수준"의 근거로 씁니다.
- 제출물 없이 안내문만 주면 작업을 시작하기 전에 기준을 잡아 주는 사전 모드로 동작합니다.
- 메일 원문은 제출물과 같은 폴더에 `pinpoint_메일_YYYY-MM-DD.md`로 저장됩니다.
- 읽을 수 있는 형식: PPTX, PDF, HTML 발표, Jupyter 노트북, 문서, Notion 공개 페이지.

## 직접 쓰려면

`SKILL.md`의 "사용자 프로필" 섹션은 작성자 본인(사회과학 전공, 인문·사회과학 관점을 덧대는 습관, 반복된 실패 패턴)을 기준으로 쓰여 있습니다. 판정의 기준점이 되는 부분이니 본인에게 맞게 고쳐 쓰세요.

## 검증

`evals/`에는 실제 채점 결과가 있는 사례 3건(실패 2, 성공 1)의 평가 기준이 있습니다. 입력 원본은 강의자료와 팀원 저작물이 섞여 있어 공개하지 않았습니다. v1은 15개 기준을 모두 통과했고, 같은 사례에서 skill 없는 기준선은 11개를 통과했습니다.
